## 2. Baseline observation and root cause

### Q10 question / expected answer / ground truth
- **Question:** “What is the procedure when multiple applicants request the same orbit-spectrum in new or unplanned bands?”
- **Expected answer:** First come first served when other conditions are fulfilled, with priority to government-owned systems in case of conflict; discussions between non-governmental applicants and the Administration to resolve conflicts; if unresolved, a common API is filed and the decision is taken at the AP S4 filing stage or later, depending on progress.
- **Relevant clause:** `3.6.8`
- **Evidence:** `EXP001-Q10-E01`, page 8, offsets `17802–18522`, chunk `satcom-ngp::page_8::chunk_0::off17796` (section `3.6.8`), text begins: “3.6.8 For 3.6.7(a) and 3.6.7(b) other conditions being fulfilled, authorisation and notification/co-ordination/registration shall be done on a first come first served basis…”

### Retrieval (unchanged, frozen)
- `Recall@5 = 1.0`, `Precision@5 = 0.2`, `MRR@5 = 0.3333`.
- Required evidence chunk retrieved at **rank 3**: `satcom-ngp::page_8::chunk_0::off17796` (distance 1.0376) overlaps `EXP001-Q10-E01`.
- Other top hits: rank 1 `satcom-ngp::page_7::chunk_3::off17330` contains 3.6.7(a)-(e) list including “(a) for new orbit-spectrum…” and “(b) in the unplanned bands…”; rank 2/4 `satcom-ngp::page_8::chunk_1::off18596` contains 3.6.10/3.6.11 and related text; rank 5 `satcom-ngp::page_7::chunk_2::off16530` not overlapping evidence.

### Baseline selection (EXP-003, `cross_reference_selection=False`)
- **Result:** answered, but `answer_supported=False`, `0/3` supported statements, `0` supported citations, no covered evidence.
- **Selected statements:** (1) 3.6.7(a)-(e) list from rank-1 chunk, (2) 3.6.10/body text from rank-2 chunk about 3.6.7(e)/operating license, (3) 3.6.10 applicability sentence “For 3.6.7(e)…” — none overlap `EXP001-Q10-E01`.
- **3.6.8 chunk not cited.**

### Exact reason 3.6.8 is not selected
1. **Lexical/query-condition mismatch via indirection:** Q10 states “new or unplanned bands / orbit-spectrum / multiple applicants request the same orbit-spectrum”. The highest lexical match is the 3.6.7 condition list (rank 1): “(a) for new orbit-spectrum…” and “(b) in the unplanned bands…” (top candidate score 11.323). Clause 3.6.8 contains the required procedure but refers to these conditions by cross-reference (“For 3.6.7(a) and 3.6.7(b)…”) instead of repeating “new orbit-spectrum” / “unplanned bands”.
2. **Sentence/unit fragmentation and weak body scores:** With sentence answer units, 3.6.8 is split into fragments. Its applicability sentence has near-zero direct query overlap in baseline scoring; body procedure sentences score low (best ~3.414, e.g. “In case two or more non-governmental systems ask for the same orbit spectrum…”), below 3.6.7 list (11.323), 3.6.10 (6.790), 3.6.11 (3.375) and other candidates.
3. **Competing applicability/reference clauses:** 3.6.10 (“For 3.6.7(e) above…”, and later “procedure described for 3.6.7(a) and 3.6.7(b)…”) and 3.6.9/3.6.11 include relevant tokens or references but are not the procedure asked for by Q10.
4. **Selection cap:** only top 3 units selected; even promoted low body fragments would not assemble the full 3.6.8 procedure without unit grouping.

This is an answer-layer selection/ranking failure, not a retrieval failure.

## 3. Hypothesis

**Document-grounded cross-reference applicability signal (general):** clauses that declare applicability with `For <clause/subclause refs>` (e.g. `3.6.8 For 3.6.7(a) and 3.6.7(b)...`, `3.6.9 For 3.6.7(c) and 3.6.7(d)...`, `3.6.10 For 3.6.7(e)...`) are procedurally linked to the referenced conditions. If referenced submarkers (e.g. `(a)`, `(b)`) correspond to list items/segments in retrieved candidates that are **lexically relevant to the question**, then the applicability clause and its contiguous body should be promoted as one answer unit. This uses source cross-references present in the document, not question-specific rules.

Mechanism details (candidate): identify query-relevant submarkers by scoring submarker-led segments in retrieved candidates (require meaningful overlap: >=2 query tokens or weighted segment score >= 4.0, to avoid incidental matches such as generic “bands” alone); for a numbered clause start matching `^(\d+(?:\.\d+)+)\s+For\s+\d+(?:\.\d+)+` whose referenced submarkers intersect query-relevant submarkers, merge the clause start with contiguous body sentences (until next numbered clause start in same chunk position) into a single verbatim source span, suppress component candidates, and promote the merged unit near top score (`max(existing, 0.95 * top_direct_score)`), below the strongest direct lexical match.

## 7. Limitations and risks

- Query-relevant submarker detection is lexical/heuristic (overlap/weight thresholds); may over-promote applicability clauses in other documents or edge cases.
- Promotion merges applicability clause body as a single unit, which can change statement granularity/citation counts (as seen Q10 citation count changed) but evidence coverage/traceability remained correct here.
- Does not solve BL-001 (Q05 retrieval miss), BL-002 (Q08 partial retrieval), BL-004/BL-005 (heading-only answer units), or semantic sufficiency gaps.
- Evaluation on 15-question set only; needs careful review before default promotion.
