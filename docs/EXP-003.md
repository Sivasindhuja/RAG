# EXP-003 — Sibling-Clause Answer Selection

Status: **Accepted** as the production answer-selection default.

Last updated: 2026-11-14.

Companion documents: `docs/PRODUCTION_SLICE.md`, `docs/ENGINEERING_LOG.md`,
`docs/PROJECT_BRIEF.md`.

---

## 1. Observed problem

PROD-001 retrieved the required evidence for Q13 (`Recall@5 = 1.0`) but selected
only one of its four category clauses:

- `4.3.1` introduction,
- `4.3.2` telephone services,
- `4.3.3` value-added services,
- `4.3.4` land mobile services.

The baseline lexical selector chose `4.3.4` plus two non-clause sentences, so the
answer covered `1/3` verified evidence units even though all required clauses were
already in the top-5. Q10 showed a related selection failure, but its evidence is
embedded inside a `3.6.8` body sentence rather than at a clause start.

## 2. Hypothesis

When the strongest sentence starts with a numbered clause, sibling clauses under
the same parent are often part of the same legal answer. Selecting them first
(up to the existing answer-length cap) should improve multi-clause evidence
coverage without changing retrieval or adding a model.

## 3. Controlled variable

Only the answer-selection rule changes:

| Arm | Selection |
|---|---|
| Baseline | Pure score order (PROD-001) |
| Candidate | If the top sentence is a numbered clause, promote same-parent clauses scoring at least 50% of the top score, then fill remaining slots by score |

Everything else is held fixed:

- `data/satcom-ngp.pdf`;
- the same 15 questions and 20 verified evidence units;
- fixed-character 1000/200 chunks (49 chunks);
- the same MiniLM embedding model;
- dense-only top-5 retrieval;
- `max_answer_sentences = 3`, `max_answer_chunks = 5`;
- citation construction and abstention policy;
- the shared support metric in `src/rag_core/evaluation.py`.

Both arms receive the **same precomputed hits** via
`GroundedPipeline.answer_from_hits`, so retrieval cannot differ between arms.
Retrieval parity with EXP-001 v3 was re-verified: Recall@5 `0.8889`,
Precision@5 `0.2533`, MRR@5 `0.7944`.

## 4. Pre-registered decision rule

Accept only if all hold:

1. statement support rate improves by at least +0.02 absolute;
2. supported answers do not decrease;
3. citation support rate does not decrease by more than 0.02;
4. abstention on the 12 out-of-corpus questions is unchanged (12/12).

## 6. What remains unfixed

- **Q05 (retrieval miss, Recall@5 = 0.0).** The required `2.5.6` evidence is not
  retrieved. No answer-layer rule can recover it.
- **Q08 (partial retrieval, Recall@5 = 0.3333).** Only `3.4.1` is retrieved; the
  answer cannot cover `3.4.2`/`3.4.3`.
- **Q10 (body-level clause).** The required `3.6.8` evidence begins inside a
  sentence that does not start with `3.6.8`, so sibling detection does not find
  it. Fixing this needs clause-aware answer units or retrieval changes, not a
  larger sibling ratio.
- **Q14** has two supported statements but both overlap the same evidence unit;
  this is an answer-completeness issue, not a retrieval failure.

## 7. Why not a cross-encoder?

During exploratory analysis, a cross-encoder sentence scorer
(`cross-encoder/ms-marco-MiniLM-L-6-v2`) was tried informally. At three sentences
it raised statement support to `17/45` but regressed Q13 to `0/3` and added roughly
456 ms per query on CPU. It was not adopted because it did not solve the main
observed failure and introduced a large latency/model dependency without a full
controlled experiment.

## 8. Threats to validity

- The 15-question set is small and was already used to inspect failures.
- The 0.5 ratio was chosen during exploratory sweeps. 0.4 and 0.5 produced the
  same aggregate result, but this is not independent confirmation.
- The rule is lexical and clause-ID based. It depends on the source preserving
  numbered clauses; it is not semantic reasoning.
- The metric measures overlap with annotated evidence, not human-judged answer
  correctness.
- A larger, independently annotated question set is required before treating the
  +0.044 statement-support delta as a general improvement.
