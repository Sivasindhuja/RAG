# EXP-004 — Constrained Generator Evaluation

Status: **Rejected for the production default.** The accepted extractive pipeline
remains the production answer path.

Last updated: 2026-11-14.

Companion documents: `docs/PRODUCTION_SLICE.md`, `docs/EXP-003.md`,
`docs/ENGINEERING_LOG.md`, `docs/PROJECT_BRIEF.md`.

---

## 1. Question

Can a small local model rewrite the already-selected, verbatim policy evidence
into a shorter and more direct answer while:

- preserving citation validity;
- avoiding unsupported policy claims;
- keeping the same abstention behaviour; and
- improving answer correctness enough to justify a production change?

This experiment changes **answer synthesis only**. Retrieval, chunking,
embedding, answer selection, answer-length caps, citations and the abstention
policy are held fixed.

## 2. Why selected evidence?

Two full-context pilot designs were tried before the full run:

1. **Free-text generation over all five retrieved chunks.**
   - `llama3.2:3b` answered Q01 with the wrong clause, echoed source metadata in
     the answer, and was slow (~37–75 s per call).
   - `qwen2.5:1.5b` was faster and more accurate on Q01/Q03, but often omitted
     citation markers; both models omitted a Q13 category.
2. **JSON generation over all five retrieved chunks.**
   - `llama3.2:3b` selected the wrong clause for Q01/Q13.
   - `qwen2.5:1.5b` produced duplicate JSON keys and repetition on Q13.

Those pilots were not advanced to the complete 15-question run. The experiment
therefore tests a narrower and safer hypothesis: generation **over the accepted
selector's own evidence**, with a machine-checkable JSON contract. This isolates
synthesis quality from evidence selection. It also means the experiment cannot
show whether a generator could recover evidence the selector missed.

The primary model is `qwen2.5:1.5b` because its pilot answers were complete
sentences and it was faster than `llama3.2:3b`. This model choice was made after
informal pilot inspection, not a controlled model comparison.

## 3. Controlled variable

| Arm | Answer construction |
|---|---|
| Baseline | Accepted extractive answer: up to three verbatim selected sentences with original citation markers |
| Candidate | Local model rewrites only those selected sentences into JSON claims; each claim names the selected evidence sentence(s) it uses; the harness attaches the original citation markers |

Everything else is held fixed:

- `data/satcom-ngp.pdf`;
- the same 15 approved questions and 20 verified evidence units;
- fixed-character 1000/200 chunks (49 chunks);
- MiniLM `sentence-transformers/all-MiniLM-L6-v2`;
- dense-only top-5 retrieval;
- EXP-003 sibling-clause selection (ratio 0.5);
- `max_answer_sentences = 3`, `max_answer_chunks = 5`;
- `AbstentionPolicy` defaults (`hard_max_distance=1.30`,
  `soft_max_distance=1.10`, `min_token_support=0.50`,
  `strict_min_token_support=0.70`).

Retrieval parity with EXP-001 v3 was re-verified: Recall@5 `0.8889`,
Precision@5 `0.2533`, MRR@5 `0.7944` (unchanged).

The generator receives only the extractive selector's selected evidence
sentences. It never sees the other retrieved chunks.

### 3.1 Generation contract

The model is asked to return JSON only:

```json
{"sentences": [{"text": "one factual claim", "sources": [1]}]}
```

Rules in the prompt:

- answer the exact question;
- use only the numbered evidence sentences;
- cite every claim with one or more evidence numbers;
- use no page numbers, section numbers or background;
- include every item for list questions;
- do not repeat claims;
- return `{"sentences": []}` if the evidence does not answer the question.

Generation settings: `temperature=0`, `top_p=0.9`, `num_ctx=4096`,
`num_predict=220`, `repeat_penalty=1.1`. `format="json"` is requested from
Ollama. All 15 generations finished with `done_reason=stop`; none was truncated.

## 4. Pre-registered mechanical gate

The experiment was accepted for further consideration only if all held:

1. all 12 out-of-corpus questions abstain (12/12);
2. no generation errors and all 15 positive responses parse as JSON;
3. zero invalid source IDs and zero uncited claims;
4. at least 90% of claims have at least 0.80 content-token coverage by their
   cited selected evidence;
5. at least 12/15 positive questions receive a generated answer.

Passing the gate was **not** sufficient: a manual audit of correctness and
faithfulness was required, and the production default could only change after a
separate integration decision.

**Mechanical outcome: FAIL**, solely on the pre-registered grounding-rate

The two claims below 0.80 were:

- Q11: `0.7500` — “current financial ability to meet the requirements” completes
  a truncated source with the generic word “requirements.”
- Q13: `0.7857` — a valid paraphrase of three category clauses adds
  “categories of domestic satellite communication services,” which is not in the
  cited statements.

Several incorrect answers had **high** token coverage: Q10's wrong claims were
both at `1.0`. Token coverage measures lexical containment, not relevance or
correctness.

### 5.2 Manual audit

The manual audit is a single-reviewer judgment recorded in
`experiments/results/exp004/manual_audit.json`. Labels:

- correctness: `correct` = all key expected facts, no material contradiction;
  `partial` = some key facts missing or material irrelevant content added;
  `incorrect` = fails to answer or contradicts expected policy facts;
- faithfulness: `grounded` = every material claim supported by cited evidence;
  `partially_grounded` = a material completion/generalisation is not directly
  supported; `ungrounded` = a fabricated material claim.

| Correctness | Extractive | Generated |
|---|---:|---:|
| Correct | 0 | 5 |
| Partial | 11 | 6 |
| Incorrect | 4 | 4 |

| Faithfulness | Extractive | Generated |
|---|---:|---:|
| Grounded | 15 | 14 |
| Partially grounded | 0 | 1 |

generator turns an incomplete heading into a fluent-looking non-answer, which is
a presentation risk rather than a quality improvement.

## 6. Decision

**Rejected for the production default.** Reasons:

1. The pre-registered mechanical gate failed (14/16 claims at >= 0.80 coverage;
   rate `0.875`, required `0.90`).
2. The manual audit found the same four incorrect answers as the extractive
   baseline (Q04, Q05, Q10, Q12), and one partially grounded completion (Q11).
3. The generator sees only the selector's evidence, so it cannot recover Q05/Q08
   retrieval misses or Q10's wrong selection. Those are upstream defects.
4. A local model adds a runtime dependency and a mean 3.76 s generation latency
   without demonstrating a correctness level that justifies replacing the
   deterministic extractive path.
5. The improvement in the “correct” bucket (0 → 5 under this reviewer's strict
   labels) is not enough to offset four still-incorrect answers and a failed
   pre-registered gate. It is also a single-reviewer judgment on a small,
   reused question set.

The extractive pipeline remains the production default. The experimental
`src/rag_core/generation.py` module is not wired into the production answer path.

## 7. What remains unfixed

- **Q05:** retrieval recall 0.0; required `2.5.6` evidence is absent.
- **Q08:** recall 0.3333; only one of three required clauses is retrieved.
- **Q10:** evidence is inside a `3.6.8` body sentence, not at a clause start;
  the selector chooses the wrong sentences.
- **Q04/Q12:** the selected sentence is a heading; the answer needs the list or
  definition that follows it. This is an answer-unit/sentence-splitting problem,
  not a generation problem.
- **Q13:** the generator inherits the selector's three-of-four categories; it
  cannot add Broadcasting unless the selector retrieves and selects it.
- **Q14/Q15:** the generated answers omit a required part present in the
  expected answer but not selected (or not in the selected sentence).

## 8. Threats to validity

- **Selected-evidence only.** This is not a full-context generator evaluation.
  The pilots showed full-context failures, but they were not run over all 15
  questions and are not reported as a complete experiment.
- **Single reviewer.** The manual correctness/faithfulness labels are one
  reviewer's judgments, not an independent annotation.
- **Small reused set.** The 15 questions and 20 evidence units were already used
  for EXP-001/002/003 and for prompt inspection. This is not a held-out test.
- **Prompt and model selection.** The prompt contract and `qwen2.5:1.5b` were
  chosen after pilots on Q01/Q03/Q10/Q13. There was no systematic model sweep.
- **Proxy metric.** Cited-token coverage is lexical containment, not entailment.
  It missed valid paraphrase and did not catch wrong Q10 claims with full
  coverage.
- **Single run.** Generation used deterministic settings, but no repeated runs or
  variance analysis were performed.
- **Local model.** A 1.5B local model is not representative of larger hosted
  models. The result does not establish that all generators fail.

## 10. Test evidence

The shared generation helper is covered by `tests/test_generation.py` (prompt
construction, source-ID mapping, invalid-source recording, empty-model
abstention, malformed JSON, duplicate-key detection and missing-field
validation). No test calls the local model.

Full suite after EXP-004: **89 passed, 25 warnings** (`python -m pytest tests -q`,
executed 2026-11-14). The warnings are the existing Chroma/Pydantic deprecation
notices.

## 11. Next work

The next experiment should address an observed upstream failure, not add a
generator on top of it:

1. **Q10 answer units:** test clause-body-aware answer units with retrieval
   held fixed.
2. **Q05/Q08 retrieval:** decide from controlled evidence whether a retrieval
   change is justified.
3. **Q04/Q12 sentence units:** split headings from the list or definition that
   follows, so the selector has a complete answer unit.
4. **Generator revisit criteria:** only after upstream coverage improves; use a
   larger/independent question set, an independent audit, and a grounding metric
   that is not fooled by relevant-looking wrong evidence.
