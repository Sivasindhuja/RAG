# EXP-001: Fixed-Character Chunking Baseline

## 1. Objective

Run the first controlled RAG experiment on the ISRO Satellite Communications
Norm, Guidelines and Procedures (SATCOM NGP) corpus using a naive fixed-character
chunking baseline, dense-only retrieval, and standard top-k retrieval metrics.

## 2. Hypothesis

Replacing the existing recursive / structure-aware chunking with a naive
fixed-character sliding window (chunk size 1000, overlap 200, step 800) will
serve as the retrieval baseline for measuring the impact of chunk granularity on
retrieval quality, before any later improvements (hybrid, rerank, expansion,
parent-child, generation) are introduced.

## 3. Configuration

| Parameter | Value |
|---|---|
| Chunking strategy | Naive fixed-character sliding window |
| Chunk size | 1000 characters |
| Overlap | 200 characters |
| Step size | 800 characters |
| Embedding model | `sentence-transformers/all-MiniLM-L6-v2` |
| Vector DB | Chroma (isolated collection) |
| Collection | `satcom_ngp_exp001_fixed_char` |
| Persist dir | `chroma_db_exp001` |
| Retrieval | Dense vector similarity only |
| Top-K | 5 |
| Metrics | Recall@5, Precision@5, MRR@5 |

The approved experiment configuration was preserved unchanged for the corrected
run: fixed-character chunking (1000 / 200 / 800), page-wise chunking, dense vector
retrieval with `sentence-transformers/all-MiniLM-L6-v2`, top-K = 5, and the
isolated EXP-001 Chroma collection. No hybrid retrieval, BM25, reranking,
query expansion, parent-child retrieval or generation was introduced.

## 4. Implementation details

- `experiments/exp001.py` implements the EXP-001 pipeline:
  - PDF page loading via `pypdf` (`load_pages`).
  - Naive fixed-character sliding-window chunker (`make_chunks`) — per page,
    chunks never cross page boundaries, offsets are page-relative, final partial
    chunks handled, chunk metadata includes source/page/start/end/chunk_index and
    best-effort article/clause identifiers.
  - Clause source spans via deterministic heading regexes (`build_clause_spans`).
  - Dense-only retrieval via raw `chromadb` client + `SentenceTransformer`
    (`build_vectorstore`, `dense_retrieve`).
  - Metrics via `compute_metrics` (Recall@5, Precision@5, MRR@5) on verified,
    character-level evidence spans.
  - Outputs written under `experiments/results/exp001_v2/` for the corrected run
    and to `experiments/results/exp001/` for the preserved original run.
- `experiments/exp001_questions.csv` — approved evaluation dataset (15 approved
  questions, `EXP001-Q01`-`EXP001-Q15`), columns:
  `question_id,question,expected_answer,relevant_clause_ids,relevant_source_pages`.
- `experiments/exp001_ground_truth.json` — verified ground-truth evidence
  manifest (character-level spans + exact supporting excerpts).
- No changes were made to the production backend (`backend/main.py`) or frontend.

## 5. Evaluation methodology

- For each of the 15 questions, dense retrieval returned the top-5 chunks.
- Ground truth is the verified evidence manifest: a retrieved chunk is relevant
  only when it overlaps an actual supporting evidence span (character-level
  overlap on the same source page).
- Recall@5 = (distinct relevant evidence units retrieved in top-5) / (total
  relevant evidence units for that question).
- Precision@5 = (retrieved chunks in top-5 overlapping ≥1 valid evidence span) / 5.
- MRR@5 = 1 / rank of first retrieved chunk overlapping any valid evidence span; zero if none.
- Evidence-level overlap details (including overlapping character counts) are
  kept in the retrieval results for inspection of partial-evidence cases.

## 6. Original run (INVALID — historical, superseded)

- Output location: `experiments/results/exp001/`.
- The original EXP-001 run used a **different question set** than the approved
  15-question dataset and mapped questions to **heading-only spans** instead of
  the actual supporting source passages.
- Because of the dataset mismatch and heading-only ground-truth spans, the
  original Recall@5 / Precision@5 / MRR@5 numbers are **not trustworthy** and must
  not be treated as an official baseline.
- The original outputs remain available for historical comparison; see
  `experiments/results/exp001/README.md`.

## 7. Observations (original run — historical only)

- Chunking behaviour tests (size/overlap/partial/page-boundary/offsets) pass.
- Several questions produced no relevant retrieval within top-5 under the
  fixed-character baseline.
- Precision@5 is low relative to recall, indicating most retrieved chunks were
  not overlapping the relevant ground-truth clauses.

## 9. Ground-truth correction (EXP-001 v2)

The original EXP-001 run was corrected before any retrieval metric was treated
as a valid baseline.

- **Ground-truth problem 1 (dataset):** the previous question set did not match
  the approved 15-question set.
- **Ground-truth problem 2 (spans):** heading-only spans were used as ground
  truth instead of the actual source passages supporting each answer.

### 9.1 Corrected dataset

- `experiments/exp001_questions.csv` now contains the approved 15 questions
  (`EXP001-Q01`-`EXP001-Q15`) with wording preserved, expected answers and
  relevant article/clause references.

### 9.2 Verified ground truth

- `experiments/exp001_ground_truth.json` holds the verified evidence manifest:
  `question_id`, `evidence_id`, source filename, source page, `clause_id`,
  `start_char`, `end_char`, `exact_supporting_excerpt` and status.
- Offsets refer to the exact `pypdf`-extracted page text used by the experiment.
- Verification: `page_text[start_char:end_char] == exact_supporting_excerpt`.
- Headings are never used as ground-truth spans; only supporting passage content
  is covered.
- For multi-clause questions (Q08: Articles 3.4.1-3.4.3; Q13: Articles 4.3.1-4.3.4)
  each required numbered clause is a separate evidence unit.

### 9.3 Ground-truth verification report

- `experiments/results/exp001_v2/ground_truth_verification.md` — per-question
  status, evidence clauses, source pages, exact excerpts, character offsets and
  whether the excerpt supports the expected answer.

## 10. Corrected experiment results (EXP-001 v2)

- Verification outcome: **all approved questions passed exact source-offset
  verification** against `data/satcom-ngp.pdf` (no unsupported or ambiguous
  question was found during verification).
- Corrected outputs are under `experiments/results/exp001_v2/`:
  corrected dataset, ground-truth manifest, ground-truth verification report,
  chunk metadata, ranked retrieval results, per-question metrics, aggregate
  metrics and experiment configuration.

These corrected metrics are computed on the verified evidence spans and the
approved 15-question dataset only. They are reported for the corrected run and
have not yet been treated as an official baseline.

## 11. Final corrected run (EXP-001 v3)

The last round of ground-truth corrections was applied and the corrected EXP-001
retrieval evaluation was re-run. The retrieval configuration was preserved unchanged
(fixed-character chunking 1000/200/800, dense retrieval, `all-MiniLM-L6-v2`, top-K = 5).

### 11.1 Ground-truth corrections applied before this run

- **Q13 (domestic satellite communication service categories):** the evidence spans for
  clauses 4.3.2 and 4.3.3 of Article 4.3 were corrected to start at the actual category
  headings (`4.3.2 Public Switched Telephone Network (domestic)` and
  `4.3.3 Value Added Services (domestic)`) so that the category names are supported by the
  source text. For 4.3.3 the heading ends page 13 while its explanatory paragraph starts page
  14; the heading-anchored evidence span is used for that unit. No artificial additional
  recall units were created.
- **Q09 (Satellite Control Centre location):** the expected answer was corrected to include
  both permitted possibilities (within the territory of India; at another location authorised
  by CAISS based on technical requirements).
- **Q10 (multiple applicants requesting the same orbit-spectrum):** the expected answer was
  corrected to capture the complete procedure from Article 3.6.8.

### 11.2 Final verification outcome (EXP-001 v3)

- All evidence units passed exact source-offset verification against `data/satcom-ngp.pdf`.
- Final report: `experiments/results/exp001_v3/ground_truth_verification.md`.

### 11.3 Final corrected metrics (EXP-001 v3)

- Aggregate Recall@5: **0.8889**
- Aggregate Precision@5: **0.2533**
- Aggregate MRR@5: **0.7944**

These are the **final corrected EXP-001 metrics**, computed with the approved retrieval
configuration on the corrected 15-question dataset and verified evidence spans.
